# Releasing AI Usage Monitor

## Versioning

SemVer (`vX.Y.Z`). No tags exist yet — the first tagged release bootstraps
both the website Releases page and the Download links.

The app uses Sparkle 2 for in-app updates. Its appcast is attached to each GitHub
Release as `appcast.xml`; the stable feed URL is
`https://github.com/thienle99-dev/ai-usage/releases/latest/download/appcast.xml`.
Updates are enabled only in builds containing `SUPublicEDKey`.

## Sparkle signing setup (once)

1. Resolve the Sparkle package and run its `generate_keys` tool from the
   `Sparkle/bin` directory in SwiftPM's artifacts. Keep the private key in the
   macOS login Keychain or a protected CI secret. Never commit or log it.
2. Store the matching public key as `SPARKLE_PUBLIC_ED_KEY` in the release
   environment. `scripts/package-app.sh` embeds it in the app's Info.plist.
3. Use a Developer ID signing identity for release builds. Local builds can
   omit it and remain ad-hoc signed; those builds do not provide a safe update
   channel.

Sparkle's official docs describe generating EdDSA keys and signing appcasts:
[Setup and publishing](https://sparkle-project.org/documentation/).

## Publish a release

```sh
# 1. Build a signed bundle with monotonically increasing version/build values
APP_VERSION=X.Y.Z APP_BUILD=X.Y.Z \
SPARKLE_PUBLIC_ED_KEY="$SPARKLE_PUBLIC_ED_KEY" \
CODE_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
./scripts/package-app.sh

# 2. Submit a temporary archive for notarization, then staple the ticket.
ditto -c -k --keepParent "dist/AI Usage Monitor.app" dist/notarization.zip
xcrun notarytool submit dist/notarization.zip --keychain-profile AC_PROFILE --wait
xcrun stapler staple "dist/AI Usage Monitor.app"

# 3. Archive only the app and preserve its framework symlinks.
ditto -c -k --sequesterRsrc --keepParent \
  "dist/AI Usage Monitor.app" "dist/AI-Usage-Monitor-vX.Y.Z-macos-arm64.zip"

# 4. Generate a signed appcast using Sparkle's generate_appcast tool.
#    Keep release archives in one updates directory when generating a feed with
#    multiple historical versions. The tool uses the signing key in Keychain;
#    in CI, pass the private key via stdin with --ed-key-file -.
mkdir -p dist/sparkle-updates
cp "dist/AI-Usage-Monitor-vX.Y.Z-macos-arm64.zip" dist/sparkle-updates/
"$(find .build/artifacts/Sparkle -type f -name generate_appcast -print -quit)" \
  --download-url-prefix "https://github.com/thienle99-dev/ai-usage/releases/download/vX.Y.Z/" \
  dist/sparkle-updates

# 5. Tag and publish the app archive and appcast.xml together
git tag vX.Y.Z && git push origin vX.Y.Z
gh release create vX.Y.Z \
  dist/AI-Usage-Monitor-vX.Y.Z-macos-arm64.zip \
  dist/sparkle-updates/appcast.xml \
  --title "vX.Y.Z" --notes-file <notes-file>

# 6. Add the website entry
#    web/src/content/releases/vX.Y.Z.md (version, date, highlights + highlightsVi)
#    Push to main — Vercel redeploys and /releases updates.
```

## Checklist

- `swift build` and `swift test` green on a clean checkout.
- `./scripts/package-app.sh` produces a working `.app` on macOS 14+ (Apple Silicon and Intel if claimed).
- Release archives are signed and notarized with Developer ID; `appcast.xml` is generated by Sparkle and uploaded with the archive.
- Confirm the app's `SUPublicEDKey` matches the private signing key and the GitHub `latest/download/appcast.xml` URL resolves after publishing.
- Release notes mention provider endpoint assumptions that changed, if any.
- Website entry added with both English highlights and Vietnamese highlights when available.
- Verify the Download flow from a Vercel preview deployment before merging to `main`.
